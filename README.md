# AI-помощник для разбора входящих заявок

Небольшое веб-приложение для первичного разбора заявок. Менеджер вводит текст, получает предполагаемую тему и черновик ответа, а затем сам решает, что отправить клиенту. Для локальной разработки используется имитатор AI без внешних сервисов и API-ключей.

Код приложения — в каталоге `neowise-candidate-triage/`.

## Требования

- Node.js 20 или новее
- Зависимости устанавливать не нужно

## Запуск

```sh
cd neowise-candidate-triage
node server.mjs
```

Откройте http://127.0.0.1:3000. Порт можно задать через переменную окружения `PORT`.

## Тест

В отдельном терминале:

```sh
cd neowise-candidate-triage
node --test server.test.mjs
```

## Как это работает

1. **Ввод** — `POST /api/triage` принимает JSON `{"text": "…"}`. Пустой, отсутствующий или нестроковый `text`, а также битый JSON → HTTP 400 и `{"status":"invalid_input"}`.
2. **AI** — ответ имитатора разбирается в API: допустимая тема (`delivery`, `pricing`, `other`) и непустой черновик. Ожидание модели ограничено **300 мс**. При таймауте, ошибке или невалидном ответе → HTTP 200 и `{"status":"manual_review","topic":null,"draft":null}`.
3. **Успех** → HTTP 200 и `{"status":"ready","topic":"…","draft":"…"}`.
4. **Страница** — при успехе показывает тему и черновик; при `manual_review` — сообщение о ручном разборе без предыдущего черновика. Нумерация запросов не даёт опоздавшему ответу перезаписать свежий результат.

Для ручной проверки сбоев в текст заявки можно добавить метки: `[timeout]`, `[error]`, `[bad-json]`, `[bad-topic]`, `[empty-draft]`.

## Польза для менеджера

Менеджер быстрее классифицирует заявку и получает черновик ответа вместо разбора с нуля; при сбое AI интерфейс явно переводит на ручную работу, чтобы не отправить устаревший черновик. Измерять можно долей заявок со статусом `ready`, временем до первого ответа клиенту и долей обращений, ушедших в `manual_review`.
